تن‌آرا — بستهٔ کامل فایل‌های سایت
نسخه: ۱۷ اکتبر ۲۰۲۶

مهم: برای به‌روزرسانی سایت، فقط خودِ ZIP را در مخزن نگذارید. ZIP را استخراج کنید و همهٔ فایل‌ها و پوشه‌های داخل آن را در ریشهٔ مخزن clinic-appointment-web آپلود/جایگزین کنید. فایل index.html باید در ریشهٔ مخزن باشد، نه داخل یک پوشهٔ اضافه.

مخزن GitHub:
https://github.com/ghad3metr-arch/clinic-appointment-web

محتویات این بسته:
- index.html: پنل مدیریت، تقویم شمسی، نوبت‌ها، مراجعین، گزارش‌ها، پرداخت و بدهی.
- booking.html: صفحهٔ رزرو عمومی مشتریان.
- gift.html و gift-card-design.png: کارت هدیه و تصویر طراحی.
- tanara-logo.jpg: لوگوی استفاده‌شده در اعلان‌ها.
- push-config.js و sw.js: تنظیمات کلید عمومی Push و سرویس‌ورکر اعلان مرورگر.
- public_booking_setup.sql: توابع و تنظیمات رزرو عمومی، فقط برای بررسی/راه‌اندازی در صورت نیاز.
- supabase-client-fields.sql: افزودن فیلد شغل و تاریخ تولد فقط در صورت نبودن آن‌ها.
- supabase/functions/tanara-push/index.ts: کد منبع تابع اعلان رزرو و یادآوری‌های زمان‌بندی‌شده.
- supabase/migrations/: فایل‌های تغییرات پایگاه‌داده و زمان‌بندی.

مراحل آپلود از گوشی اندروید:
۱) ZIP را با برنامهٔ فایل‌ها استخراج کنید.
۲) در GitHub مخزن clinic-appointment-web را باز کنید، Add file و سپس Upload files را بزنید.
۳) همهٔ فایل‌های داخل پوشهٔ استخراج‌شده را انتخاب کنید؛ خود فایل ZIP را به‌جای محتویات آن آپلود نکنید. پوشهٔ supabase باید با زیرپوشه‌هایش حفظ شود.
۴) Commit changes را بزنید. Netlify طبق اتصال موجود، پس از Commit باید Deploy جدید را شروع کند. تا پایان Deploy فایل‌های قدیمی را جداگانه حذف نکنید.

وضعیت زیرساختی که بررسی شد:
- پروژهٔ Supabase فعال است؛ تنظیم رزرو عمومی وجود دارد و تابع Edge به نام tanara-push نسخهٔ ۶ فعال است.
- اعلان رزرو عمومی اصلاح شده تا درخواست صفحهٔ رزرو با قالب مورد انتظار تابع هماهنگ باشد و هر نوبت بیش از یک بار اعلان رزرو تولید نکند.
- زمان‌بندی سروری tanara-reminder-push فعال است و هر دقیقه بررسی می‌کند. آزمون مستقیم زمان‌بندی از داخل پایگاه‌داده پاسخ HTTP 200 و نتیجهٔ موفق با صفر یادآوریِ سررسیدشده برگرداند.
- یادآوری‌های انتخابی روی خود نوبت در ستون‌های reminder_minutes و reminder_sent_at ذخیره می‌شوند. نوبت‌های قدیمی به‌طور پیش‌فرض «بدون یادآوری» هستند؛ برای تغییر آن‌ها، وارد تقویم شمسی یا فهرست نوبت‌ها شوید و «تنظیم یادآوری» را بزنید.
- زمان یادآوری با منطقهٔ زمانی تهران محاسبه می‌شود. یادآوری سروری نیاز ندارد صفحهٔ سایت باز بماند؛ اما برای دریافت اعلان گوشی، باید مرورگر/گوشی اجازهٔ اعلان داده باشد و اشتراک Push آن دستگاه فعال باشد.
- یک آزمون واقعی ارسال Push به گوشی شما از داخل این محیط ممکن نیست؛ بنابراین پس از Deploy، حتماً روی گوشی یک اعلان آزمایشی/رزرو آزمایشی را بررسی کنید.

پیامک مخاطبین:
دکمهٔ «ارسال پیامک» کنار مراجعین، برنامهٔ پیامک گوشی را با شماره و متن آماده و قابل ویرایش باز می‌کند. ارسال نهایی نیازمند زدن دکمهٔ ارسال در گوشی است. ارسال خودکار یا انبوه پیامک از طرف سایت فعال نیست و به سرویس‌دهندهٔ پیامکی و تنظیمات/اعتبار آن نیاز دارد.

گزارش‌ها و پرداخت‌ها:
- پرداخت متصل به نوبت بر اساس تاریخ انجام نوبت در گزارش درآمد ماهانه/سالانه شمرده می‌شود، نه تاریخ تسویه.
- پرداخت بدون اتصال به نوبت ناچار بر اساس تاریخ ثبت پرداخت گزارش می‌شود؛ در دادهٔ فعلی چند پرداخت بدون اتصال به نوبت وجود دارد. برای گزارش بر اساس تاریخ خدمت، باید آن پرداخت‌ها به نوبت مربوط وصل شوند.
- کارت هدیه، تقویم شمسی، شمارهٔ تماس‌ها، فهرست ساده‌شدهٔ مراجعین و فرم پرداخت متصل در بسته نگه داشته شده‌اند.

نکته دربارهٔ فایل‌های SQL:
فایل‌های supabase/migrations/ توضیح و نسخهٔ کنترل‌شدهٔ تغییرات هستند. تغییرات مربوط به جدول اعلان تکراری، ستون‌های یادآوری و زمان‌بندی در پروژهٔ متصل Supabase اعمال شده‌اند؛ صرف آپلود این فایل‌ها در GitHub آن‌ها را دوباره اجرا نمی‌کند. public_booking_setup.sql و supabase-client-fields.sql را فقط در صورت مشاهدهٔ خطای مشخصِ RPC یا ستون ناموجود و پس از بررسی اجرا کنید؛ اجرای تکراری/بی‌مورد لازم نیست.

کنترل نهایی:
ZIP از نظر ساختار آرشیو، وجود فایل‌های محلی موردنیاز و نحو JavaScript بررسی شده است. آزمون ورود واقعی، رزرو عمومی زنده، نمایش Push روی دستگاه شما و ارسال پیامک از گوشی باید بعد از انتشار و روی دستگاه خودتان بررسی شود؛ این موارد را بدون آزمون واقعی نمی‌توان تضمین کرد.
